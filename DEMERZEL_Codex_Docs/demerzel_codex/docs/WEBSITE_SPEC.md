# DEMERZEL Website Specification

## 1. Product vision

DEMERZEL Enterprises should be presented as a professional
field-technology company rather than a generic online electronics store.

Core positioning: - Technology for the field. - Observe. Navigate.
Protect. Explore.

The website should support: - product discovery - technical evaluation -
product comparison - direct purchase where appropriate - quote/enquiry
workflows - professional/institutional procurement - support and
equipment management - future integration with DEMERZEL FIELD

## 2. Primary navigation

Header: - DEMERZEL - Products - Solutions - Industries - Brands -
Projects - Resources - About - Search - Account - Contact

## 3. Homepage

### Hero

Headline: "Technology for the field."

Supporting copy: "Precision equipment for wildlife, forestry, surveying,
security and exploration."

CTAs: - Explore Products - Find the Right Equipment - Talk to an Expert

### Built for the Field

Four entry points: - Observe - Navigate - Monitor - Explore

## 4. Product listing

Required: - search - category filters - brand filter - application
filter - specification filters where applicable - price filter only when
verified prices exist - availability filter only when real inventory
data exists - sorting - pagination/infinite loading - compare selection

Do not show fake inventory or prices.

## 5. Product detail

Required sections: 1. product identity 2. product gallery 3. short
source-grounded description 4. applications / use cases 5. key features
6. technical specifications 7. comparison with related models 8.
documents 9. quote/cart CTA 10. related products 11. support/service 12.
enquiry form

### Product CTA rules

For lower-complexity retail products: - Add to Cart - Add to Wishlist -
Compare

For professional/high-value equipment: - Request a Quote - Contact an
Expert

Do not assume which products require a quote until commercial rules are
defined.

## 6. Solutions

Routes: - /solutions/wildlife-conservation - /solutions/forestry -
/solutions/security-surveillance - /solutions/survey-mapping -
/solutions/research - /solutions/outdoor

Each solution page: - hero - problem/use case - recommended equipment
categories - relevant products - workflow - downloadable resources -
enquiry CTA

Do not invent project outcomes or technical capabilities not supported
by the source.

## 7. Industries

Potential routes: - Forest Departments - Wildlife & Conservation -
Government - Security & Surveillance - Research & Education - Survey &
Mapping - Outdoor & Adventure

Use industry pages to explain applications, not to make unsupported
institutional claims.

## 8. Brands

Each brand page: - brand name - products in DEMERZEL catalogue -
catalogue context - relevant categories

Do not state "authorized distributor", "official partner", "exclusive
dealer" or equivalent unless verified.

## 9. Projects

Project pages should be CMS-driven.

Fields: - title - location - industry - challenge - solution -
equipment - implementation - outcome - media - documents

Only publish verified project details.

## 10. Resources

Types: - catalogues - datasheets - guides - manuals - FAQ - articles

Every downloadable technical document should be linked to the correct
product.

## 11. Customer account

Dashboard: - orders - quotes - equipment - projects - service requests -
documents - profile

Professional organization account: - organization - users - assigned
equipment - projects - service - procurement history

## 12. Support

Features: - product lookup - serial number - warranty - service
request - repair status - document downloads - contact support

Do not publish warranty duration until commercially verified.

## 13. UX requirements

Every major async UI needs: - loading state - empty state - error
state - retry action

Every form needs: - validation - success state - failure state -
accessible labels - server-side validation

## 14. SEO

Each product should generate: - title - meta description - canonical
URL - Open Graph metadata - structured data where accurate - breadcrumb
data

Do not generate SEO text containing specifications that are not in the
product record.

## 15. Accessibility

Target: - keyboard navigation - visible focus - semantic headings -
labels for inputs - accessible dialogs - accessible tables - alt text -
sufficient contrast - reduced-motion support

## 16. Responsive design

Breakpoints should support: - mobile - tablet - desktop - large desktop

Product specification tables need a deliberate mobile presentation; do
not simply overflow the entire page.

## 17. Visual direction

Use: - premium technical aesthetic - dark/earthy field imagery -
restrained typography - large product photography - technical diagrams -
clear specifications - high information density where appropriate

Avoid: - generic marketplace appearance - excessive gradients - fake
reviews - fake trust badges - fake statistics - stock imagery presented
as real DEMERZEL projects
